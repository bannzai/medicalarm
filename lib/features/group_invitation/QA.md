# group_invitation QA

招待コード入力・参加画面と、参加後のマルチユーザー同期（本機能の中核・後から直しにくい）の確認。

前提: 2 ユーザーを用意する。
- ユーザー A: シミュレータ 1 台目。共有グループを作成し、薬（スケジュール付き）を登録し、招待コードを発行しておく
- ユーザー B: **2 台目のシミュレータ**（sim-boot で別名シミュレータを起動）を推奨。1 台でやる場合は `xcrun simctl shutdown <UDID>` → `erase` で新規匿名ユーザーにする（Keychain 復元のため erase 必須。root QA.md 参照）が、A のセッションが失われ相互確認ができなくなる

## 3. マルチユーザー同期（A・B 両視点）

- [x] B の参加後、A のグループ設定のメンバー一覧に B がリアルタイムで現れる
- [x] B がグループ切替チップで共有グループに切り替えると、A が登録した薬が表示される
- [ ] B が服薬チェックすると、A の服薬記録一覧にもB の記録がリアルタイムで現れる
  - ❌ 失敗: 【重大・データ消失バグ】共有薬に2つ目のスケジュールを追加した状態で、片方のユーザーが別デバイスでチェックボックスを操作すると、その薬の**全スケジュールの服薬記録が両ユーザーの画面から消える**（チェック状態が false に戻り、履歴タブも「服薬履歴がありません」になる）。詳細は本ファイル末尾の「発見した重大な不具合」を参照。issue: https://github.com/bannzai/medicalarm/issues/253
- [x] A から見て B の記録に記録者ラベルが表示される（B の displayName 未設定時は「メンバー」フォールバック）。A 自身の記録にはラベルが出ない
- [x] B がグループ設定で表示名を設定すると、A 側の記録者ラベル・メンバー一覧に反映される
- [ ] B の端末で共有薬のリマインダーローカル通知がスケジュールされる（スケジュール時刻を数分後に設定して通知バナー表示を確認）
  - ⏭️ スキップ: 時間経過を伴う実機確認のため今回のセッションでは未実施
- [x] 非作成者 B の通知個別設定を開くと、初期値で Critical Alert とアラーム機能（AlarmKit）が OFF になっている（共有薬の Critical Alert が勝手に鳴らない設計）
- [x] A が記録済みのスケジュールは B 側でも記録済み表示になる（重複記録にならない）

注: 服薬記録時の他メンバーへの FCM push の**実配信確認は本 QA の対象外**（ユーザー判断で除外。関数の実行は Cloud Logging の sendMedicationRecordNotification のログで確認できれば十分）。

## 発見した重大な不具合（リリースブロッカー候補）

issue: https://github.com/bannzai/medicalarm/issues/253

### 事象

共有グループの薬に対して、片方のユーザーが服薬記録をチェックした状態で、**別デバイス（別ユーザー）がその薬の別スケジュールをチェックすると、両方のスケジュールの服薬記録がその場で消え、以後も戻らない**。

- チェックボックスが未チェック状態に戻る（両ユーザーの画面で同時に発生）
- 服薬履歴タブ（`lib/features/medications_histories/page.dart`、日付範囲クエリで生データを直接表示）でも「服薬履歴がありません」になる
- アプリの完全終了 → 再起動後も再現したまま（新規 Firestore リスナーでも空を返す）ことを確認しており、UI のキャッシュ不整合ではなく **Firestore 上のデータそのものが失われている、または到達不能になっている**

### 再現手順

1. A（オーナー）が共有グループに薬（例: 共有薬X, 10:00スケジュール1つ）を登録
2. A がそのスケジュールをチェック（服薬記録を作成）→ A・B 双方の画面で正しくチェック済み表示になることを確認
3. B が同じ薬を編集し、スケジュールをもう1つ追加（10:00 のまま可）して保存
4. B がその新しいスケジュール（2つ目、未チェック）のチェックボックスをタップ
5. → **A・B 双方の画面で、両方のスケジュールが未チェックに戻り、履歴タブも空になる**

再現率: 手順どおりに実施した2回とも100%再現。単一デバイスのみでの操作（手順3・4を同一デバイスで行う）では発生しないことを確認済み — **2台のデバイスが同時に同じ画面を開いている状況（クロスデバイスの並行操作）が引き金になっている**。

### 調査結果

- `lib/features/medications/page.dart` の `MedicineTileScheduleRow` で、チェックボックスの状態変化を購読する `isChecked.addListener(...)` が `build()` 直下で無条件に呼ばれており、`useEffect` でライフサイクルをスコープしていない。実機ログで同一タップに対し `call_register_reminder_notification` が2回発火することを確認しており、リスナーの重複登録が起きている
- この重複登録を `useEffect` + `removeListener` の一般的な Flutter Hooks パターンで修正して同一手順を再実行したが、**症状は解消しなかった**。したがってリスナー重複だけが根本原因ではなく、別の要因（`lib/provider/medication_history.dart` の `MedicationHistoryTake.call()` が既存の `medicationHistory` の有無に関わらず常に `database.medicationHistoriesReference().doc()`（新規ランダムID）に書き込んでいる点など、クロスデバイスの並行書き込み・読み取りタイミングに関わる複合的な要因）が関与していると考えられる
- 根本原因を完全に特定できず、対症療法的な修正を確信を持って適用できなかったため、**本 QA セッションではコード修正を行っていない**（検証できない修正を完了と報告しないため。加えた変更は revert 済み）

### 影響

服薬管理アプリの核心機能（服薬記録）が、複数人での使用中に**記録が消える**形で壊れる。介護・育児等での「代わりに服薬管理をする」という本アプリのコンセプトに対し、記録消失は誤って重複服薬・過小服薬を招くリスクがある安全上の懸念。

### 推奨対応

リリース前に開発チームでの詳細調査・修正を強く推奨する。再現手順は上記のとおり安定して再現するため、修正後の検証は容易。
